# D415 与 iPlanner 规划观察窗口

入口 `g1_iplanner_viewer.py`。不创建 DDS、运动客户端或轨迹跟随器，不发送机器人命令。
2026-10-16起，D415默认采集1280×720、15fps；RGB/深度面板按16:9显示。旧480p回放保持4:3比例并在两侧留黑，点击黑边不选目标。目标像素和投影始终使用原图坐标及该帧实际内参。
窗口显示 RGB、对齐深度、俯视规划路径、目标与输入帧号。相机采集和 HTTP 规划分属线程，
等待规划时画面继续更新；路径注明规划输入帧号及结果年龄，不冒充与最新画面严格同步。
默认使用最新模型框自动设置规划目标，不需要手动点击。此窗口没有运动控制接口；任何真机运动命令由用户手动执行，助手不直接启动。

运行[单次跟随诊断](README_G1_ONCE_FOLLOW.md)时，窗口只读该入口的 `follow_live.json`，显示
实际跟随器使用的路径及当前SLAM局部坐标，右下注明 `FOLLOWING IN PROBE - VIEWER IS READ ONLY`。
此时不另发独立规划请求；运动开始后模型框隐藏。收到STOPPED或0.5秒未更新时隐藏执行路径。
监控窗口的Q只关闭显示；停止真机请在运动入口终端按Ctrl+C。

当前测试顺序及各终端命令见[实时画面与单次旋转决策测试](README_LIVE_MONITOR_TEST.md)。
先打开窗口，再手动运行旋转决策命令：运动前清除旧框/旧路径，停车且新决策返回后在实时RGB里更新框。
窗口启动时跳过历史响应；不会因为重新打开窗口而把昨天的框画到今天的画面。

## 启动服务

保持已更新的D415 TCP服务运行。本机服务可同时供预览和采集使用，最多4个接收端；机器人上的旧服务仍为单客户端。iPlanner 使用已有环境和权重：

```bash
cd /home/yile/projects/unitree-g1-isaaclab-project
IPLANNER_PYTHON=/home/yile/miniconda3/envs/isaacsim/bin/python \
  bash scripts/isaacsim_lavira_g3_interface_g1/run_iplanner_local.sh
```

没有升级 GPU 驱动、修改官方相机 SDK 或修改仿真入口。

## 实时观察

```bash
cd /home/yile/projects/unitree-g1-isaaclab-project
source /home/yile/projects/.venvs/unitree_g1/bin/activate
python scripts/isaacsim_lavira_g3_interface_g1/g1_iplanner_viewer.py
```

默认读取 `outputs/d415_rotation_model/` 下窗口打开后写入的每条新模型决策，在左上实时RGB叠加绿框；用框底边中心的原图像素及当前深度设置目标。每次新决策替换框和规划目标，STOP/无目标响应清除旧路径，旧目标仍在途的HTTP结果不会显示成新目标路径。

以目标像素周围 7×7 有效深度的第30百分位反投影，转换为名义相机前/左二维目标，沿目标方向提前0.5m设置规划目标
（可用 `--stand-off-m` 修改）。持续使用新深度重规划，蓝线为路径，黄色圈为目标，
绿色点为提前停止的规划目标，白点是名义局部原点。停车显示阶段目标像素固定，不进行目标跟踪。
深度无效时不生成默认前进目标。`S` 保存，`Q`/Esc 或 Ctrl+C 退出窗口。

布局是左上RGB与模型框、右上深度、左下路径/目标、右下规划状态。中文目标名称和决策编号显示在窗口标题。
相机读取失败或图像超过1秒未更新时清除路径并标记STALE，后台尝试重新连接；收到新鲜帧后重新规划，不放宽接收端新鲜度校验。SDK服务自身因USB断开退出时仍需要恢复相机服务，窗口可保持等待。
关闭窗口时，Qt可能在可见性查询中返回 `NULL guiReceiver`；该情况按正常退出处理，回收取图和规划线程，不记为规划失败。已有DejaVu系统字体时为本进程修正OpenCV wheel中不存在的字体目录，不修改Python环境或系统库。

保留人工点击模式用于独立排查规划器：

```bash
python scripts/isaacsim_lavira_g3_interface_g1/g1_iplanner_viewer.py --target-source manual
```

仅人工模式接受RGB点击和 `C` 清除目标；切换模式需要重新启动窗口。

默认每0.5秒提交最新任务，HTTP请求串行执行；新目标选择后旧目标结果不显示。
每个成功结果保存最新预览、路径、原始规划输入 RGB-D 与 K，输出目录自动生成在
`outputs/iplanner_viewer/run_.../`，新结果覆盖同一运行的 latest 文件，不覆盖其他运行。

默认模式的目标来自最近一次模型响应，窗口本身不调用远端模型；模型的新响应由用户另行手动启动的采图/决策入口产生。`latest_target.json`记录目标来源；每条规划的 `model_decision`记录响应文件、决策编号和框，便于核对框与路径属于同一决策。
本步检验实时相机、目标投影、iPlanner请求及可视化，不等于模型到行走的完整导航闭环。固定框不补偿全景回正偏差、相机或物体移动；位置变化后，框和由当前深度得到的目标都可能偏离真实物体，不能把它当作当前帧的新检测或已验证的世界目标。

### 最近决策的实时绿框（2026-10-16）

默认同时监听 `outputs/d415_rotation_model/`，将新模型决策的框叠在实时RGB上，每次决策替换、STOP等无目标决策清除。目标名称和决策编号在窗口标题里。此绿框是“停车时最近一次模型选择”，不跟踪。`g1_rotation_model_probe.py` 在调用旋转子进程前写 `display_motion.json`，窗口清除更早的框和路径；旋转失败/停止也不恢复旧框，直到新响应到达。独立遥控或其他运动入口不会自动通知本窗口，开始前可在图像窗口按 `H` 隐藏旧框，或退出窗口；不要把该显示通知当作运动检测器。默认黄色十字是模型框底边中心，用于当前深度投影和规划；显式 `--target-source manual` 时才由人工点击独立选择规划目标。
可用 `--model-results /本次任务结果目录` 绑定正式任务的响应文件。旧480p结果不拉伸到720p；非前方目标等待正式真机转向并重新取前视帧的确认。
具体文件约定、方向限制和多接收端语义见[相机说明](camera_d415/README.md#实时rgb中的模型目标框)。

## 用上一次模型结果重放规划

```bash
python scripts/isaacsim_lavira_g3_interface_g1/g1_iplanner_viewer.py \
  --replay-run outputs/d415_rotation_model/run_20261015_160933_f63564c8
```

读取保存的完整全景和 `model/response.json`，使用模型选择的前方原图、对应深度及 bbox
底边中心，调用一次真实 iPlanner。仅支持 NAVIGATE/forward，不自动转机器人。
`--headless` 只保存结果。记录模式图像明确标注 RECORDED，不连接实时相机。

## 坐标和精度边界

本入口明确不加载安装外参，目标采用 `X=depth, Y=-(u-cx)*depth/fx` 的名义相机前/左
坐标，Z不参与二维目标。路径为既有服务返回的局部预览，没有转换到 torso 或 SLAM 世界系。
0.5m是该近似坐标中的距离，不是已验证的机器人到物体净空。
`fear` 仅显示原始网络分数，不作为避障通过或安全保证。
送入原HTTP协议前，深度限定0.1～5m，其余清零，避免其uint16的0.1mm编码超过6.5535m后回绕。

正式行走前还需确定相机/机器人/SLAM坐标转换，并处理原真机入口默认小速度命令的跟踪问题。
G3阶段进度返回的解析错误也需要单独排查，不能由本地iPlanner测试替代。

### 椅子案例与当前结论

实时人工选点、深度更新和HTTP重规划均已现场运行。每次请求通常约40～50ms是部分现场读数，
不是长期延迟保证。路径输入帧与最新RGB会有时间差，窗口分别标注。

保存帧47254中椅背深度中位数约1.123m，名义坐标下路径中心线到所选椅背表面最近约10.04cm，
规划目标到该表面约10.28cm。未应用外参、地面高度或实测身体轮廓，不能当作最终净空。
此前8.47cm使用图像下部更广范围的近处点，口径不同。

固定目标的合成深度对照引起路径变化，说明网络不是完全忽略深度；合成对照不是实物避障成功。
当前服务只生成并插值路径，没有额外几何碰撞拒绝。`latest_plan.status=PASS`只代表路径格式与数值有效，
不代表目标处于自由空间、路径无碰撞或机器人能执行。低fear也不能证明净空足够。

**当前结论：实时规划链路已打通，实际避障能力待验证，尚未进行本次路径的行走执行。**
